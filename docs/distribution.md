# 配る人向け：渡し方と、保険の登録

## 基本：相手の会社で登録してもらう

このプログラムは、**使う人の会社のEntraで1回登録**して使うのが基本です（READMEの手順3）。相手の会社の中だけで完結するので、配る人の会社は関わりません。相手の会社の情報システム担当にとっても、自分たちで登録したアプリのほうが許可しやすくなります。

配る人がすることは、GitHubのURLと頼み方を渡すだけです。送る文面の例です。

```
OneNoteをClaude Codeから使うための設定です。Claude Codeに次の文を貼ってください。

https://github.com/zenbuai-tech/ClaudeOneNoteGraph-public のREADMEに従って、私の会社のOneNoteに接続する設定をしてください。画面の操作とログインは私がやるので、1つずつ案内してください。

途中で、御社のMicrosoft Entraでこのプログラムを登録する手順があります（5分ほど）。ご自身で登録できない場合は、御社の情報システム担当の方に、READMEの手順3を頼んでください。
```

## 保険：自社の登録を「他社でも使える」ようにしておく

相手の会社で登録できない場合に備えて、配る人の会社の登録を他社でも使える設定にしておけます。この場合、相手は登録を飛ばし、配る人のアプリIDで使います（READMEの「配る人のアプリIDを使う場合」）。

| | 基本（相手の会社で登録） | 保険（配る人の登録を使う） |
|---|---|---|
| 相手の会社でEntraの登録 | 要る（5分ほど） | 要らない |
| 管理者の許可 | 会社の設定しだい | 多くの会社で要る（「未確認」の表示が出るため） |
| 配る人が登録を消したとき | 影響なし | 相手も使えなくなる |

登録は [Microsoft Entra管理センター](https://entra.microsoft.com/) の「アプリの登録」で行います。

### 1. アプリを登録する（初めての場合）

「アプリの登録」→「新規登録」で、次のように入れます。

| 項目 | 入れる値 |
|---|---|
| 名前 | `Claude OneNote Graph`（相手の許可画面に出る名前です） |
| サポートされているアカウントの種類 | **任意の組織ディレクトリ内のアカウント（マルチテナント）** |
| リダイレクトURI | 種類は「パブリック クライアント/ネイティブ（モバイルとデスクトップ）」、URIは `http://localhost:8765/callback` |

クライアントシークレット（パスワードのような鍵）と証明書は**作りません**。このツールは使いません。

### 2. すでに「自社だけ」で登録している場合

「アプリの登録」→ 対象のアプリ →「認証」を開き、「**Supported accounts**」タブで「シングル テナントのみ」を「**すべてのテナントを許可する**」に変えて保存します（古い画面では「サポートされているアカウントの種類」を「任意の組織ディレクトリ内のアカウント（マルチテナント）」にします）。

配る相手の会社が決まっているなら、「**特定のテナントのみを許可する（プレビュー）**」を選び、相手の会社のテナントIDだけを足すほうが安全です。知らない会社からは使えなくなります（2026-10-18時点でプレビューの機能です）。

切り替えても、自社の人の使い方は変わりません（`.env` のテナントが自社のテナントIDのままでも動きます）。

### 3. 安全のための設定

- **「認証」→「設定」タブ（古い画面では「詳細設定」）→「パブリック クライアント フローを許可する」を「無効」（古い画面では「いいえ」）にして保存します。** アプリIDを悪用した「だましのログイン」（確認コードを入力させる方式）を防ぐためです。このツールのふつうのログイン（ブラウザ）には要りません。代わりに `login --device-code` は使えなくなります。切り替えたら、配る人のパソコンで `login` が通ることを確かめます。
- 「APIのアクセス許可」には、Microsoft Graphの**委任されたアクセス許可**の `Notes.ReadWrite`（チームのノートを使うなら `Notes.ReadWrite.All`）と `offline_access` だけを入れます。アプリケーションの許可（利用者なしで動く権限）は足しません。
- （任意）「ブランディングとプロパティ」で、ホームページのURL（このGitHub）と発行元ドメインを入れておくと、相手の管理者が確かめやすくなります。
- （任意）**発行元の確認**を済ませると、許可画面の「未確認」の表示が消えます。相手の会社の設定によっては、管理者なしで本人が許可できるようになります。Microsoft AI Cloud Partner ProgramのIDが要ります。

### 4. 保険を使う相手に渡すもの

- **アプリIDだけ**を渡します。アプリの「概要」にある「アプリケーション (クライアント) ID」です。
- **テナントID（ディレクトリ ID）は渡しません。** 他社の人は `organizations` を使います。
- アプリIDは秘密の情報ではありません。ただ、どの会社が配っているかが分かり、だましのログインに使われる余地もわずかにあります。そのため、GitHubなど公開の場には載せず、メールやチャットで個別に渡します。

## 止めるとき

| 止めたい範囲 | すること |
|---|---|
| 相手の会社で登録したアプリ | 相手の会社の管理者が「アプリの登録」から削除する |
| 保険の登録（すべての会社） | 配る人がアプリの登録を削除する |
| 保険の登録（ある会社だけ） | その会社の管理者が「エンタープライズ アプリケーション」でこのアプリを削除する |
| ある人だけ | その会社の管理者が、その人のサインインのセッションを取り消す。本人は `logout` で手元の認証情報を消す |

## 公開リポジトリに入れないもの

アプリID・テナントID・組織名・`.env`・`config.local.json`・認証情報は、公開リポジトリに入れません（`.env` などは `.gitignore` で除外済みです）。公開する前に、次のコマンドで番号が入っていないか確かめます。`00000000-…` や `11111111-…` のような見本の番号だけが出ればOKです。

```sh
grep -rEoh --exclude-dir=.git '[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}' . | sort | uniq -c
```

## 確認状況（2026-10-18）

- READMEの手順3（新しい登録、パブリック クライアント フローは無効のまま）からログイン・読み書きまでは、Macで確認済みです。
- 保険の登録（すべてのテナントを許可する）、別の会社のアカウント、管理者の許可は、**まだ確かめていません。**
